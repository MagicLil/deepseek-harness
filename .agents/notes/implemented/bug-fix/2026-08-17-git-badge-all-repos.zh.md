# Agent Note: Activity-bar Git badge sums every project repo

Status: implemented

[English](2026-08-17-git-badge-all-repos.md) | 中文

## 问题

活动栏 Git 泡泡只数一棵工作树：上次 Git 页选中的仓，否则会话 cwd，否则第一个子仓。多仓项目文件夹（VS Code 多根父目录，旁边并列 `sanmu_qd` / `sanmu_hd` / …）图标只反映其中一个，和选择器对不上。

## 决策

`readGitBadgeSnapshot` 用和 Git 选择器同一套种子（`gitWorkspaceSeeds` + `discoverGitRoots`），把发现到的每棵工作树的暂存 + 未暂存加总。快照里的 `root` 仍是上次选中的仓（还在集合里时），否则用第一个发现的根。可见上限是 `1k+`（1000 及以下显示原数）。兄弟 / 父级轨道上的其它项目不计入，与选择器一致。

Git 页仍先按当前选中仓画一次，再发布加总，避免切换或当前仓失败时把其它仓的数盖掉。

## 考虑过的其他做法

**继续只数一个仓，只把 `99+` 上限抬高。** 否决：用户要的是整个项目的合计。单个脏仓 220 本来就会封顶；缺的是其它兄弟仓。

**把所有已登记 Workspace 都算进去，包括其它轨道。** 否决：选择器已经滤成当前项目文件夹。图标必须和那份名单一致。

**徽章改由 Git 页独占，去掉活动栏自己的 watch。** 否决：资源管理器或搜索在前时图标也看得到，所以 [计数泡泡那篇](2026-08-16-git-count-badges.md) 才不挂 SCM 也要拉 status。

## 后果

打开多仓文件夹时，每个发现到的根会打一次 `gitStatus`（先发现，再重读）。两次之间消失的子仓会被跳过。旧笔记里「先用第一个子仓，直到 Git 页公布根」那句由本篇取代。
