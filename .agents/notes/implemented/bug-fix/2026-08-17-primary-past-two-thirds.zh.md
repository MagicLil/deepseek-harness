# Agent Note：左侧栏可拖过窗口三分之二

Status: implemented

English | [2026-08-17-primary-past-two-thirds.md](2026-08-17-primary-past-two-thirds.md)

## 问题

Git / 资源管理器列仍然停在 `floor(视口 * 2 / 3)`。再往右拖会被夹住，宽一点的 Git 面板（提交图、门禁、文件列表）吃不到空编辑器。分隔条命中区只有 8px 且居中：一半压在侧栏的 Windows 滚动条和行内按钮上，抓住可见分割线常常毫无反应。

## 决策

左侧栏不再和对话列共用 2/3。`workbenchMax` 改为 `视口 - ACTIVITY_WIDTH - 160`，和底栏「给编辑器留 160px」同一习惯。对话列仍是三分之二。竖向分隔条加宽到 16px（4px 在侧栏、12px 在编辑器），并标 `-webkit-app-region: no-drag`，避免 Electron 把这条带子当成拖窗口。

## 考虑过的替代

**保留 2/3，只加宽分隔条。** 否决：截图里侧栏已经很宽；找到手柄后再拖还是撞上比例上限。

**让左侧栏占满整窗（编辑器 0）。** 否决：编辑器轨道必须还是一列，空状态文案和随后打开的文件 Tab 不能被收成 0 宽格子。

## 后果

把 Git 拖得很宽会关掉对话，编辑器可能只剩 160px。桌面端必须先重建 `ui-layout`（`lib/client.js`），新上限和分隔条才会画出来。
