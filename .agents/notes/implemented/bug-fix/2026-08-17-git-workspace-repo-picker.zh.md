# Agent Note：加工作区后 Git 仓库下拉

Status: implemented

[English](2026-08-17-git-workspace-repo-picker.md) | 中文

## 问题

源代码管理顶栏只显示当前会话原来的那一个仓库。用户从右侧栏再登记一个工作区之后，没有仓库下拉，切不过去。原先只把「别的工作区路径」当成 Git 根去探测，`git status` 说不是仓库就丢掉。已经打开了一个子仓时再把外层父目录加进来（常见操作），父目录本身不是仓库，子仓就不会出现。同一文件夹的 `D:\repo` / `D:/repo` 也用 `!==` 比较。

## 决策

`discoverGitRoots` 从会话 cwd 和每一个已登记工作区路径出发。种子本身是工作树就留下；种子是 `git-unavailable` 时，贡献它的一层可见子目录（和 cwd 不是仓库时的旧回退一样）。`git-failed` 的种子不当成父目录。根路径用斜杠和盘符大小写归一后去重，所以 `D:\repo` 和 `D:/repo` 算同一个。仓库多于一个时，Git 页顶栏画出下拉。

## 考虑过的其他做法

**继续只探测工作区路径本身。** 否决：把 `deepseek-harness` 的父目录加进来是正规登记，那个父目录不是仓库。

**递归扫磁盘找 `.git`。** 否决：更早的 Git 发现笔记已经否决过；边界仍是已登记工作区路径加一层子目录。

## 后果

加了兄弟仓库或「多项目父目录」之后打开 Git，会出现仓库下拉。每个本身不是仓库的已登记文件夹会多打一次 `listEntries`。
