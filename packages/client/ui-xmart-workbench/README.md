# @deepseek-ai/dsh-client-ui-xmart-workbench

English | [中文](README.zh.md)

X-Mart workbench plugin: the Cursor-style occupants of the frame-declared `menuBar`, `activityBar`, `primarySidebar`, `workbench`, and `bottomPanel` slots. The product application menu is File / Edit / Go / View / Terminal / Help (新会话, 打开工作区, 保存, 关闭编辑器, 设置, 查找, 替换, 在文件中查找, 转到文件 / 行 / 定义 / 实现 / 引用, Explorer / Search / Git, sidebars, terminal). Desktop paints the same HTML `menuBar` inside the 32px title track (dropdowns portal so the strip cannot clip them); accelerators still ride the Electron application menu. File → Settings dispatches `dsh:open-settings`; File → Save dispatches `dsh:workbench-save`; Edit → Find / Replace dispatch `dsh:workbench-find` / `dsh:workbench-replace` to the mounted editor. Edit → Find in Files (Ctrl+Shift+F) and View → Search switch the sidebar to the search pane and dispatch `dsh:workbench-search` to focus its input. Go → File dispatches `dsh:workbench-quick-open`; Go → Line / Definition / Implementation / References / Hover dispatch `dsh:workbench-editor-action`. The activity bar switches Explorer / Search / Git in the left primary sidebar (clicking the active icon collapses that track). The Git icon shows a green bubble with staged + unstaged; the SCM section headers show the same counts on the right. Settings also stay on the far-right session rail. `WorkbenchColumn` fills the center editor track with file tabs; that track stays mounted. The primary-sidebar occupant remembers open/closed plus the last non-zero width per session in `dsh.xmart.workbench` (default open at 260px). Activity lives on the per-session tab persist (`dsh.xmart.workbench.tabs.<sessionId>.activity`). The layout store itself stays transient and does not persist.

`apply` provides `ctx.xmartWorkbench` and stacks a `theme.overrideTokens` layer that remaps DeepSeek-blue accent aliases (selected tabs, send button, focus rings, markdown links) to the 万物智汇 green `#5BB73B`. Success / error / warn tokens stay as they are. Other client plugins register tab types, file viewers, and activity-bar entries through `registerTab` / `registerFileViewer` / `registerActivity` (each call returns a disposer for the fiber). Built-in activities are `explorer`, `search`, and `git`; marketplace plugins add more. Unknown persisted activity ids display as Explorer. `openTab` / `closeTab` / `activateTab` / `openFile` / `setActivity` mutate the per-session tab list. Switching conversations in the same project folder (including a blank New Session) inherits the previous session's editor tabs, activity, explorer expansion, and primary-sidebar width (terminal tabs stay behind); a session in another folder starts from its own persist. Settings → Workbench lists every registered type with an enable switch (`dsh.xmart.workbench.prefs`): off hides the type from the `+` menu and refuses new `openTab` calls; tabs that are already open stay. An open tab whose type is not registered renders a placeholder card that names the type id and carries a close-tab button, so the tab can be cleaned up without waiting for the plugin to return.

Explorer rows and editor tabs use the full [Material Icon Theme](https://github.com/material-extensions/vscode-material-icon-theme) (file names, compound extensions, special folders such as `src` / `.github`). Associations and SVGs are generated into `icon-theme-data.ts` and baked into the client bundle because the plugin server only serves `client.js`.

Built-in shell types are hidden from `+`: `explorer` (lazy tree of the current session folder — same resolution as Git; a title-row refresh icon re-lists the disk, and new file/folder live on the row context menu), `git` (Cursor-style Source Control: filename + dimmed directory rows, green count bubbles on Staged Changes / Changes and on the activity-bar Git icon, hover stage-unstage-discard, section stage-all / discard-all, click opens a unified diff, a pre-commit checklist that summarizes this change set, recommends `package.json` gates from dirty paths, shows each command/status, and only creates a commit after the user confirms — failed gates can be handed to the session Agent in one click; a sparkle button that asks the host for an auxiliary commit message, with a local `type: 中文` draft filled in first; branch switch/create, user-clicked fetch/ff-only-pull/push sync, a painted commit graph with author names and no leading hash; clicking a row opens that commit's per-file diff, while ref pills still switch or detach; if the session cwd is not a repo, the panel probes immediate child folders; diff tabs pin that selected root so git is not run against the parent folder), and `terminal` (line-oriented host PTY via `host.terminal*`; at most 6 per session; hiding the bottom panel does not kill the PTY). The bottom panel also hosts singleton **Problems** and **Checks** tabs (View → Problems / Checks): Problems aggregates open-editor LSP markers plus the latest check parse; Checks discovers `typecheck` / `lint` / `test` / `build` scripts from the root `package.json`, runs them through `remote.workspaceChecks`, shows the exact argv, supports related-to-git-dirty runs, keeps the last log in `localStorage`, can re-run failed scripts when the session stops running, and can send failed rows to the Agent. The `search` activity is Cursor-style global text search over the session folder, backed by `host.search` (the packaged ripgrep binary — the same one the agent's grep tool spawns): typing debounces 250ms (Enter searches immediately), toggles cover match case / whole word / regex, an ellipsis row adds include / exclude globs, results group by file with highlighted match runs, and clicking a row opens the editor at that line. Results are capped (500 by default) and a cut result says so; the query and results live in memory per session, so switching activities keeps them. Visible `+` type: `demo`. Hidden file tabs: `editor` (Monaco + Shiki, drafts, Ctrl/Cmd+S, Ctrl+F/H find, Ctrl+P file palette, Ctrl+G go to line, F12 / Ctrl+click definition, Ctrl+F12 implementation, hover, Shift+F12 references on `.java` / `.ts` / `.js` / `.vue`; language servers start when the project folder is opened, not on the first source file; Markdown preview; Gradle / ignore / `.npmrc` / `.prettierrc` / `.env*` pick a grammar by file name), `diff` (unified text from `host.gitDiff`, Shiki tokens on add/del backgrounds like the editor), `image` and `binary` (placeholders plus open-in-system), and a leftover `file` stub for old persisted tabs. `openFile` matches a viewer (priority-descending detect-then-exts) and opens `editor` / `image` / `binary`, deduped by path. Viewers: `binary-download` (NUL detect), `image`, `markdown`, and catch-all `code`. Explorer/editor drafts and expanded directories persist at `dsh.xmart.workbench.files`. Agent file-tool events bump a refresh nonce and a per-path reload token (D7), which also refreshes the Git tab. Both bundle patches disable `ui-editor`, so the conversation view ring is chat plus trajectory.

The Git repository picker probes every registered Workspace path and updates when the Workspace registry changes. The current session repository stays selected while new valid repositories become available in the same picker; duplicate Workspace paths inside one repository collapse to the canonical root returned by `host.gitStatus`.

The shell slots are declared by ui-layout, and `settings.section` by ui-settings-general, so `apply` uses `slots.inject()` to register for each declaration lifetime and re-register after the declaring slot is restored.

## Model Experience

None, as the workbench is browser chrome; nothing here reaches a model request.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **Rename and delete are disabled** — the workspaces remote has no FS rename/delete yet; the explorer menu shows those rows as unavailable.
- **Chat path clicks still open the OS app** — intercepting `workspaces.openPath` from conversation chips needs a host seam in `ui-conversation`. Explorer right-click keeps "open in system app".
- **Image tabs are placeholders** — in-column preview needs a host `readFileBytes` RPC; the tab shows the path and a system-open button.
- **Terminal is line-oriented** — Enter sends one line and waits for idle. Python REPL is the acceptance bar; full-screen TUIs (vim/htop) are out of scope. A session whose agent has no `ctx.terminals` shows an unavailable note instead of a fake shell.
- **Diff is unified text** — not a Monaco DiffEditor dual pane. Git sync is user-clicked only (fetch, `--ff-only` pull, push). It never force-pushes and never writes `user.name` / `user.email`. Creating a commit from the Git panel also never pushes and never writes Git identity: the pre-commit checklist requires a user confirm, and recommended gates must be passed or skipped. The commit graph follows HEAD (not `git log --all`), paints thin rails with quarter-circle merge elbows in a shared column, marks merges with a ring-and-dot and other commits with a solid dot, and uses a short stub when the other parent is not nearby; clicking a row opens `host.gitDiff` with `commit` (first-parent patch). Remote/tag pills can still detach HEAD. It is not a full Git Graph extension (no octopus layout or interactive rebase). The Cursor-style **Review dock** above the composer (`agentReview` host Remote) lists per-turn Agent `write`/`edit` shadows for Keep/Undo without git stage. The sparkle button asks `host.gitSuggestCommit`; the host owns the prompt and logs `session/git-commit-llm-request`. A local conventional-commit draft (`feat`/`fix`/`chore` + Chinese subject) fills the box first.
- **badge, urlTarget, and plugin-owned settings rows are not on the descriptor** — v1 keeps enable switches only.
- **Enable maps and file chrome are localStorage, not `settingsScope`** — they do not sync across devices.
- **Layout preference is transient until the occupant restores it** — a full reload resets the layout store's primary width to the default open size; the occupant reapplies the session persist after mount.
- **Concession can hide an open preference** — a narrow viewport may derive a zero primary track without clearing the stored preference; widening restores it.
